# Agent 接续工作协议

## 接手流程

1. 读取 `AGENTS.md`。
2. 读取 `docs/ai-secretary/00-status.md`。
3. 读取目标阶段和相关验收条目。
4. 运行现有测试，建立基线；不能假设前一 Agent 的结论正确。
5. 检查 `reports/` 中最近一次报告。
6. 选择一个最小可交付任务，不跨阶段大范围改动。
7. 先增加或修改测试，再实现代码。
8. 更新报告、状态和待办。

## 每次工作结束必须留下

- 修改文件列表。
- 完成的验收 ID。
- 执行过的命令及结果。
- 未完成的工作和阻塞原因。
- 给下一个 Agent 的明确下一步。

## 推荐任务格式

```markdown
### TASK-XXX：实现 <功能>

输入：
- 当前已有接口/fixture/页面

目标：
- 可观察的行为

验收：
- AC-XXX
- AC-YYY

测试先行：
- 先新增哪些测试

完成产物：
- 代码
- 测试
- 报告
```

## 不能做的事情

- 不得仅修改状态文件来伪造完成。
- 不得删除失败测试或降低断言来制造 GREEN。
- 不得把真实服务调用偷偷加入默认测试。
- 不得在没有报告的情况下跨越阶段。
- 不得依赖聊天上下文中未写入文件的决定。

## 交接摘要模板

```markdown
## 交接摘要

- 当前阶段：
- 本次完成：
- 已通过验收：
- 测试结果：
- 报告：

- 下一步最小任务：
- 需要用户决策：
```
