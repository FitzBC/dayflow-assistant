# 阶段推进计划

## 阶段总览

| 阶段 | 名称 | 主要产物 | 阶段出口 |
|---|---|---|---|
| P0 | 项目基线 | 规范、目录、验收矩阵、报告模板 | Agent 可接续、标准可执行 |
| P1 | Web 业务原型 | 可运行前端、任务模型、Mock 解析、基础排程 | 浏览器可完成核心闭环 |
| P2 | AI 接口与数据层 | LLM Adapter、结构化输出校验、本地持久化 | AI 可替换、数据可恢复 |
| P3 | Capacitor Android 壳 | Android 构建、原生桥接、权限处理 | APK 可安装、页面可运行 |
| P4 | 语音与本地提醒 | SpeechRecognizer、通知、延期/完成 | 真机可语音和提醒 |
| P5 | 日历与动态重排 | Calendar Provider、预览确认、重排 | 真实日历安全同步 |
| P6 | 稳定性与发布 | 性能、隐私、安全、回归、发布包 | 可交付测试版 |

## P0：项目基线与可验收机制

### 功能范围

- 统一项目章程和 Agent 工作规范。
- 定义领域对象、状态枚举和验收标准。
- 定义测试命令、报告格式和证据目录。

### 交付物

- `AGENTS.md`
- `docs/ai-secretary/00-status.md`
- `docs/ai-secretary/01-project-charter.md`
- `docs/ai-secretary/02-phase-plan.md`
- `docs/ai-secretary/03-acceptance-matrix.md`
- `docs/ai-secretary/04-verification-and-reporting.md`
- `docs/ai-secretary/05-agent-handoff.md`
- `docs/ai-secretary/06-technical-baseline.md`

### 验收标准

- 新 Agent 只读 `AGENTS.md` 和 status 文件即可理解当前阶段。
- 每个后续阶段都有明确输入、输出、测试和出口条件。
- 测试报告模板包含命令、环境、通过/失败数量、覆盖率和证据路径。

## P1：Web 业务原型

### 功能范围

- 今日页、任务页、秘书输入页、设置页。
- 文本输入和模拟语音输入。
- Mock 任务解析：日期、时间、时长、优先级、重复规则。
- Inbox、任务状态、完成、延期。
- 固定 fixture 日历事件。
- 简单确定性排程：寻找空闲时间块。
- 计划预览和确认。

### 测试要求

- 领域模型单元测试覆盖正常、缺字段、冲突和边界日期。
- 解析器 fixture 测试至少覆盖 20 个中文输入样例。
- Playwright 覆盖：输入 → 解析 → 确认 → 生成计划 → 完成/延期。
- 关键领域代码覆盖率目标 ≥ 80%。

### 阶段出口

浏览器中不依赖真实大模型和真实日历即可完成一次完整业务闭环，并生成报告和截图。

## P2：AI 接口与数据层

### 功能范围

- `LLMAdapter` 接口和 Mock 实现。
- JSON Schema 校验和错误恢复。
- 本地存储任务、计划、提醒、审计记录。
- 解析失败时保留原始输入并进入 Inbox。
- 模型请求最小上下文策略。

### 测试要求

- 合法 JSON、字段缺失、类型错误、模型超时、模型返回自然语言等场景。
- 重复提交不产生重复任务。
- 数据迁移和重新打开应用后数据仍存在。
- 不把 API Key 和敏感 fixture 写入仓库。

### 阶段出口

模型供应商可以替换；真实模型失败时业务仍不丢数据；所有模型写入动作经过 schema 和权限校验。

## P3：Capacitor Android 壳

### 功能范围

- Capacitor Android 工程。
- Debug APK 构建。
- Web 前端在 Android WebView 中运行。
- 原生与前端通信协议。
- Android 返回键、生命周期、状态恢复。

### 测试要求

- Gradle 构建成功。
- 至少一台模拟器或真机安装成功。
- 页面切换、旋转/重启、返回键不丢失任务。
- Web 构建产物与 Android 壳版本一致。

### 阶段出口

能安装 APK，能完成 P1 的核心流程，且报告包含设备型号/系统版本和安装截图。

## P4：语音与本地提醒

### 功能范围

- 按住说话、松手结束。
- 识别中、成功、无权限、无网络、取消和超时状态。
- Android 通知权限引导。
- 开始前提醒、截止前提醒、延期、完成。
- App 被杀或设备重启后的提醒恢复。

### 测试要求

- 真实设备语音成功率测试至少 20 条固定语料。
- 通知点击能打开对应任务。
- 完成或延期后原提醒不会重复触发。
- 重启应用/设备后未来提醒仍能恢复。
- 不允许用前端 `setTimeout` 作为生产提醒机制。

### 阶段出口

在指定测试设备上，语音和提醒核心流程可重复通过；失败时有明确用户反馈。

## P5：日历与动态重排

### 功能范围

- 读取系统日历。
- 固定事件、弹性任务、习惯任务分类。
- 计划预览：展示新增、移动、取消的时间块。
- 用户确认后写入 AI 专用日历。
- 冲突发生后局部重排。
- 撤销最近一次计划变更。

### 测试要求

- 固定事件绝不被移动。
- 计划不会重叠，任务不超过用户工作结束时间。
- 任务截止时间不可被排到之后。
- 同一计划重复应用不会创建重复日历事件。
- 取消权限或日历不可用时不丢任务，并可降级为本地计划。

### 阶段出口

真实日历测试账号中完成读取、预览、确认、写入、重排和撤销闭环。

## P6：稳定性与发布

### 功能范围

- 崩溃、网络、模型、权限和数据库异常处理。
- 隐私说明、数据删除和导出。
- 性能和电量测试。
- 发布构建、版本号、回滚说明。

### 阶段出口

- 关键 E2E 100% 通过。
- 无 P0/P1 级缺陷。
- 领域核心覆盖率 ≥ 80%。
- 连续 3 次完整验证流程通过。
- 形成测试版发布报告。
